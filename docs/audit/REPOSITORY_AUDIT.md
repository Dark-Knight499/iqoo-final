## 1. Executive summary / what the product actually does

This is a mobile-styled **React/Vite web application**, not an installed native phone app. With onboarding already completed (or with the separate legacy FastAPI service running), it navigates creator/project dashboards, persists profiles/projects/bookmarks in browser storage, shows a script editor and scrolling teleprompter, requests a live camera preview, allows choosing assets, and runs visually polished creator/media/editor flows. Most claimed AI, media analysis, editing, recording, and export in **this checkout** are simulations: the editor plays no video, the camera screen does not record video, media import loads a fixture, and export returns a fabricated blob URL. There is no measured Snapdragon inference.

The checkout contains **two distinct Python backends** and two frontend API clients. The untracked `backend/` serves `/api/*` with static fixtures and optional OpenAI text/JSON calls. The legacy FastAPI app in `legacy/Creator-AI-Creative-Intelligent-Studio/` provides genuine HTTP routes for profiling, scraping/trends, clipping and publish-job bookkeeping, but mixes live inputs with templates/hard-coded metrics and misleading success signals. On first load `src/shared/state/app.store.ts:39` forces onboarding; `src/features/onboarding/OnboardingFlow.tsx:43-79` calls legacy `/profiling` before completion. If only the root fixture backend runs, onboarding cannot finish through the UI. Root Vite proxies `/api` to port 8000 while the legacy client calls `http://localhost:8000` directly; the two Python services both claim port 8000 and cannot simultaneously occupy it by default.

**Confidence:** source-traced high for routing/data origins and definite code defects; tested only root TypeScript (`tsc --noEmit`) and root fixture API pytest (1 passed), the recording branch TypeScript check, and the dynamic-editor branch Node media tests (3 passed). No successful live legacy integration, browser E2E, model inference, phone recording, or end-to-end export was demonstrated in this audit.

## 11. Technical risks

- **Unreproducible committed snapshot:** root working tree has 31 modified tracked and 106 untracked paths *before audit docs*. Root backend and API clients are untracked; other feature worktree is dirty; nested Git histories are distinct. A build of just committed `main` is not this audit target.
- **Presentation/provenance:** labels assert "45 TOPS", "NPU accelerated", active hardware, accurate latency, face tracking and fabricated view/follower figures without evidence of measurement or device binding (`backend/app/api/endpoints.py:82-119,37-46`, legacy dashboard and VLM service). OpenAI cloud generation is described as on-device spatial vision.
- **Backend deployment:** Vite proxy `/api` forwards to 8000, legacy API client bypasses proxy; dev port collision and phone/browser localhost. Legacy API key settings are in a local `.env` (not disclosed here). Postgres credentials in example/Compose are development defaults. Broad CORS (`allow_origins=["*"]`), no authentication and mutable global state preclude trusting multi-user isolation.
- **Storage/consistency:** legacy jobs JSON and DB can diverge silently; profile report output can exist despite DB error. LocalStorage can exceed limits for metadata and cannot persist blob data by URL. Branch render servers store media on disk; they are not present in root and need retention/error/port review before shared use.
- **Tests are narrow:** root npm scripts have no `test`/`lint`; Python root test checks seven fixture endpoints, not client integration, OpenAI, media, publishing or hardware. Legacy tests include network/file-writing paths, so they were not run in this no-modification audit. The independent dynamic media test verifies its separate branch, not root.
